# Slice 6.2 — `driver-rt`: Transport, Virtqueues, DMA Window, Driver Slots — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything a virtio driver stands on, proved by one device answering: virtio-blk boots at
slot 11, is handed its device by the kernel, negotiates, enables a queue on kernel-reserved DMA
memory, claims its interrupt line and prints the disk's capacity.

**Architecture:** The kernel probes the 32 virtio-mmio slots at boot, and for each driver with a
device and an ELF maps one register page, allows one INTID and maps one contiguous 64 KiB DMA run,
all reported through two `SYS_GETINFO` selectors. `driver-rt` holds the shared `IrqLine`, a
`Transport` trait with a virtio-mmio v2 implementation, and a split virtqueue. Decision logic (probe
assignment, feature negotiation, queue layout and ring discipline) is pure and host-tested; register
access and traps are thin.

**Tech Stack:** Rust (`no_std` kernel and EL0 drivers, host tests in `kernel-shared` and
`driver-rt`), virtio 1.x over MMIO, GICv3, aarch64 QEMU `virt` 11.0.3, `dprint`.

**Spec:** [`../specs/2026-11-09-driver-rt-design.md`](../specs/2026-11-09-driver-rt-design.md),
decisions `T1…T14`, under the phase decisions `H1…H12` of
[`../../plans/phase-6-virtio.md`](../../plans/phase-6-virtio.md). Read the spec before Task 1. Where
this plan and the spec disagree, **the spec wins** and the plan gets corrected.

## Marker text (fixed here, used by several tasks)

| Line                                                                                                              | Printed by         |
| ----------------------------------------------------------------------------------------------------------------- | ------------------ |
| `[virtio] slot=<n> pa=<hex> id=<id> ver=<v> drv=<name>`                                                           | kernel, assigned   |
| `[virtio] slot=<n> pa=<hex> id=<id> ver=<v> skip=no-driver` / `skip=<no-module\|duplicate> for=<name>`            | kernel, unassigned |
| `[virtio] refuse slot=<n> id=<id> page=<hex> shared`                                                              | kernel, T4 rule 1  |
| `[devmap] vblk va=<hex> pa=<hex> intid=<n>`                                                                       | kernel             |
| `[dma] vblk va=0xc0000000 pa=<hex> pages=<DMA_RUN_PAGES>`                                                         | kernel             |
| `[diag vblk] no device`                                                                                           | virtio-blk         |
| `[diag vblk] virtio ok features=<hex> capacity=<sectors> qsize=<n> slot=<n>`                                      | virtio-blk         |
| `[diag vblk] virtio FAIL step=<getinfo\|dma\|transport\|id\|features\|queue\|status\|irq\|irq-deny\|irq-extra> …` | virtio-blk         |
| `[diag tty] getinfo.deny ok n=<count>` / `[diag tty] getinfo.deny FAIL case=<i> rc=<rc>`                          | TTY                |

The legacy refusal is `step=transport version=1 need -global virtio-mmio.force-legacy=false`.

## Review Focus

1. **A boot with the stubs on clobbering a driver's privileges** (T2). Expected: stubs and drivers
   never share a priv id. Pinned by two `const` asserts in Task 1 and by the default boot being the
   one that carries the `virtio ok` marker.
2. **A device whose `QueueNumMax` is 0 or below 8.** Expected: 0 is `step=queue` and a degraded
   driver; a smaller power of two is used as-is; nothing indexes past the ring. Host tests in Task 8
   (`queue_layout` rejects 0 and non-powers of two) and the clamp test in Task 8.
3. **Ring index wrap.** The available and used indices are free-running `u16`s; at 65535 → 0 the
   slot arithmetic must still be `idx % size`. Host test in Task 8.
4. **Descriptor exhaustion.** `add` on a queue without enough free descriptors returns `None` and
   leaves the free list intact. Host test in Task 8.
5. **A config space that never settles.** `config_read` retries on a changing `ConfigGeneration` a
   bounded number of times and then returns the last read rather than hanging the driver. Host test
   in Task 7 against the mock transport.

pub struct QueueLayout { pub size: u16, pub desc_off: usize, pub avail_off: usize, pub used_off: usize, pub bytes: usize }

Layout rule: descriptor table at offset 0 (16 bytes each), available ring next aligned to 2
(`flags`, `idx`, `ring[size]`, `used_event`, all `u16`), used ring next aligned to 4 (`flags`, `idx`

little-endian. Ring memory is shared with the device: read and write it with `read_volatile` /
`write_volatile` on the slice's pointer, and put a `fence(SeqCst)` between writing a ring entry and
publishing `avail.idx`.
