# Slice 6.5 — TTY RX: PL011 receive interrupt + `CDEV_READ` + a VFS that does not block — Implementation Plan

**Goal:** a byte arriving on the PL011 reaches `read(0)`, and a process waiting for one does not
stop VFS serving everybody else.

**Spec:** [`../specs/2026-11-23-tty-rx-design.md`](../specs/2026-11-23-tty-rx-design.md), decisions
`R1…R12`, under the phase decisions `H1…H12` of
[`../../plans/phase-6-virtio.md`](../../plans/phase-6-virtio.md). Where this plan and the spec
disagree, **the spec wins** and the plan gets corrected.

## Global Constraints

- **Branch `feature/6.5-tty-rx`.** Every commit `--signoff`ed and GPG-signed; never `--no-gpg-sign`,
  never `--no-verify`. **No push, no PR, no CI trigger.**
- **SPDX header** first in every new `.rs` file.
- **No ABI value moves** (D8, R10). `gen-c-headers` output is diffed against `main`.
- **No kernel change** unless Task 0 or a later task finds one is needed (R9); a finding goes in the
  ledger before the code. No `#[cfg(test)]` under `kernel/src/`.
- **No polling** (I12): TTY blocks in `receive` between interrupts; VFS never spins on `EAGAIN`.
- **No new `unsafe`** outside `drivers/tty/src/pl011.rs`.
- **Overflow-safe arithmetic** in the ring's index math and the park table's sequence numbers.
- **Boots.** `$S` is the session scratch directory. Build first (`MINIXRS_SDK=/nonexistent cargo
  build -p minixrs-kernel --target aarch64-unknown-none --release`), then `MINIXRS_SDK=/nonexistent
  MINIXRS_ROOT=<disk|ramdisk> timeout 600 cargo run -p minixrs-kernel --target aarch64-unknown-none
  --release < <(tools/feed-console.sh $S/<name>.log) > $S/<name>.log 2>&1`. One boot at a time.
  Iterate and mutation-test stub-free (`--no-default-features`), judging by the specific marker.
  Read `check-boot-log.sh`'s whole output; apply the starved-boot check before believing a missing
  marker.
- **Mutation discipline** per
  [`testing-and-markers.md`](../../conventions/testing-and-markers.md#mutation-testing).
- **Counts in markers come from constants**, never typed into a driver.
- **Markdown** wraps at 100; `~/.dprint/bin/dprint fmt` + `check` and `python3
  tools/check-md-links.py` on anything edited.

## Marker text (fixed here)

```text
[diag tty] irq ok rounds=2                 (unchanged)
[diag tty] rx on                           RX masks set after the proof's last round
[diag tty] rx overflow                     forbidden; once per boot
[diag tty] rx FAIL storm                   forbidden; once per boot
[diag tty] rx FAIL enable rc=<rc>          forbidden
[diag vfs] cons.park                       first park of the boot
[diag vfs] cons.beside ok                  first file VFS_READ completed while a read is parked
init: stdin ok n=15
init: stdin FAIL n=<n> first=<byte in hex> forbidden (substring `stdin FAIL`)
```

`15` is `CONSOLE_PROBE.len()`; the string is `minix.rs stdin\n` and lives in one place the feeder
can be checked against (a host test in init compares the constant with the bytes
`tools/feed-console.sh` holds).

## Review Focus

1. **Peek-then-consume** — a failed `SYS_SAFECOPY` consumes nothing. Host test on the ring's
   `peek`/`consume` split; mutation 7.
2. **Ring wrap** — push/peek across the wrap point, full drops the newest, `len` never exceeds
   `TTY_INPUT_MAX`. Host tests with the ring pre-advanced to the last index.
3. **`CDEV_READ` length rules** — `len == 0` before the empty check (answers `0`, not `EAGAIN`);
   negative `len`; bad minor; clamp to `min(len, buffered, CDEV_MAX_IO)`. Host tests in `cdev.rs`.
4. **Park table** — one entry per slot; oldest-first by sequence; `free` on exit; an entry whose
   stored endpoint differs from the slot's current occupant is not retried. Host tests in `park.rs`;
   mutation 8.
5. **No reply to a notification** — VFS's `NOTIFY` arm sits before the request dispatch and does not
   fall into `reply()`. Mutation 4.
6. **No lost wakeup** — TTY records the waiter before replying `EAGAIN`; VFS parks before its next
   `RECEIVE`; the waiter is notified after `IRQ_ENABLE`. By reading, plus mutation 3.
7. **Acknowledge-then-drain** (R4) — the order in `irq.rs`, and that `IRQ_ENABLE` follows the drain.
   Mutations 5 and 6.
8. **The walk stops at the first `EAGAIN`** and replies to every reader served before it; a count or
   an error both free the entry.
9. **`open.deny`'s count** is recomputed from its table after `read-console` goes.
10. **The feeder** writes exactly once, only after `cons.beside ok`, and cannot keep a finished
    boot's pipeline alive.

## Tasks

### Task 0: Measure first (R11)

Throwaway probe code in TTY, never committed. Results in the ledger.

### Task 1: the input ring and the read validation (R1, R3)

**Files:** `drivers/tty/src/input.rs` (new), `drivers/tty/src/cdev.rs`, `drivers/tty/src/main.rs`
(the `mod` line only).

- `Ring`: `push` (drops the newest when full, returns whether it stored), `peek(&mut [u8]) ->
  usize`, `consume(n)`, `len`, `dropped`. `TTY_INPUT_MAX = 256`.
- `cdev::validate_read(req) -> Result<usize, i32>`: `validate_write`'s rules for a read.
- `cdev::read_len(want, buffered) -> usize`.

**Proves it:** `cargo test -p minixrs-tty` (Review Focus 1–3).

### Task 2: VFS parks and retries (R2)

**Files:** `servers/vfs/src/park.rs` (new), `servers/vfs/src/main.rs`.

- `park.rs`: the table (`NR_PROCS` entries keyed by proc slot), `park`, `free`, `oldest`,
  `any_parked`; host tests (Review Focus 4).
- `main.rs`: the loop handles a `NOTIFY_MESSAGE` from the console driver before dispatch, with no
  reply; `do_read` returns a "parked" outcome the loop does not reply to; the retry walk;
  `do_pm_exit` frees the entry; `cons.park` and `cons.beside ok`.
- Inert at boot until Task 3: nothing answers `EAGAIN` yet.

**Proves it:** `cargo test -p minixrs-vfs`; a stub-free boot's markers unmoved.

### Task 3: TTY receives (R1, R4, R5) and init stops probing `read-console` (R7)

**Files:** `drivers/tty/src/{pl011,irq,main}.rs`, `userland/init/src/main.rs`,
`kernel-shared/src/callnr.rs` (doc comment), `tests/qemu-boot.expected`,
`tests/qemu-boot.forbidden`.

- `pl011.rs`: `getc() -> Option<u8>`, `set_rx_masks`, `ack_rx`.
- `irq.rs`: the proof hands over to the RX service; `irq FAIL extra` deleted; the storm guard.
- `main.rs`: the `CDEV_READ` arm, the waiter, `EIO` with no line.
- init: the `read-console` probe deleted, `open.deny`'s count recomputed. Same commit, because the
  probe would otherwise park init forever.

**Proves it:** stub-free boot: `rx on` present, `irq ok rounds=2` present, every prior marker
present, `irq FAIL` absent.

### Task 4: the proof child and the feeder (R7, R8)

**Files:** `userland/init/src/main.rs`, `tools/feed-console.sh` (new), marker files.

**Proves it:** a fed stub-free boot prints `cons.park`, `cons.beside ok`, `init: stdin ok n=15`, in

### Task 5: CI (R8)

## Ledger

One entry per task: its commit, what was verified, and every ruling made in it.

- **Task 0 (2026-11-23; no commit of its own — throwaway probe in TTY, restored from a scratchpad
  snapshot, `grep -rn MUTATION` clean).** Stub-free boots, QEMU 11, Homebrew's edk2. **R11.1:**
  `UARTLCR_H = 0x70` — the firmware leaves the FIFO **enabled** (`FEN`) — and `UARTIFLS = 0x12` (RX
  trigger at half). One byte fed on its own still raised the line: one notification, `n=1`,
  `UARTRIS = 0x30` (`RXRIS` with `TXRIS`; `RTRIS` clear), so QEMU raises RX on the first byte
  whatever the trigger level says. Three bytes written together arrived in one notification, and 36
  written together were all drained in one (more than the 16-deep FIFO: QEMU refills it as the loop
  empties it). `IRQ_ENABLE` answered `OK` each time and the next notification arrived, with the ICR
  write placed before the drain (R4's order). **R11.2:** with stdin at EOF (`< /dev/null`) QEMU
  carries on and the boot is unchanged, so the feeder need not hold its stdout open for QEMU's sake.
  **R11.3:** five bytes on stdin from time zero **never reach TTY** — the firmware or Limine
  consumes them before the kernel starts. R8's gate on a log marker is therefore load-bearing, not
  just causal tidiness. **R11.4** (budget) is Task 6's.

- **Task 1.** `input.rs` (`Ring`, `TTY_INPUT_MAX`) and `cdev::validate_read` / `read_len`; 26 new
  host tests, 34 in the crate, written against stubs first (23 failing). Verified: `cargo test -p
  minixrs-tty`, clippy `-D warnings`, the nested bare-metal TTY build warning-free. **Ruling:**
  `validate_read` shares one private `validate` with `validate_write`, so a zero-length read with a
  bad minor or grant id is an error, not `0`. The spec's R1 said "`len == 0` answers `0` before
  anything else, as `CDEV_WRITE` does", which `CDEV_WRITE` does not; **the spec was corrected** to
  say what both directions do. *If wrong:* `validate_read` gets its own order, one function.
  **Carried to Task 3:** three "Until Task 3 wires RX in" `allow(dead_code)`s to delete (`input.rs`
  module level, `validate_read`, `read_len`); the once-per-boot `rx overflow` print is the caller's,
  not the ring's.

- **Task 2.** `park.rs` (`ParkTable`: `park`, `free`, `evict_stale`, `oldest`, `any_parked`) and the
  loop's notification arm, `ReadOutcome::{Reply, Parked}`, `retry_parked`, the exit free and the two
  markers in `main.rs`; 15 new host tests (14 failing against stubs), 91 in the crate. Verified:
  `cargo test -p minixrs-vfs`, clippy, fmt, the nested bare-metal build warning-free, and a
  stub-free boot with every `[diag vfs]` and `init:` line present and `cons.park` absent — the path
  is **inert until Task 3**, so nothing here has been exercised by a boot yet. **Rulings:** (a) the
  table is a `main`-frame value like `GrantPool`, not an `UnsafeCell` static like `fd.rs` — no new
  `unsafe`; (b) a re-park replaces the slot's entry and goes to the back; (c)
  `evict_stale(m_source)` runs on every ordinary request — the spec's "stale endpoint" rule had no
  mechanism, since VFS has no process table, and **the spec gained the bullet**; (d) the notifier
  check is `m_source == tty`, not a device-table lookup — **the spec was corrected**, 6.6 widens it;
  (e) `cons.beside ok` needs a real `FS_READ` round trip (a zero-length file read does not count)
  and prints just before that read's reply is sent; (f) any `NOTIFY_MESSAGE`, from anyone, is now
  dropped without a reply. *If wrong:* each is local to `park.rs` or one arm of `main.rs`; (c) costs
  one line to remove. **Noted, not fixed here:** `GRANT_SLOTS`'s doc says VFS's stack is one page —
  Task 8's sweep.

- **Task 3.** `pl011.rs` (`getc`, `set_rx_masks`, `ack_rx`); `irq.rs`'s `IrqProof` renamed
  `IrqService` with phases `Proof(rounds)` / `Rx` / `Stopped`, `irq FAIL extra` deleted, the storm
  guard as a pure `EmptyRun`; `main.rs`'s `CDEV_READ` arm over `cdev::read_plan`, the
  `cdev::Waiter`, notify-after-re-arm; init's `read-console` probe deleted (`open.deny` 12 → 11,
  constant, const-assert and marker literal moved together); `CDEV_READ`'s doc comment; the two
  common marker files. 15 new host tests (10 failing against stubs), 49 in the crate. No kernel
  change (R9 holds). Verified: host tests, clippy, fmt, the nested bare-metal build warning-free;
  stub-free boot A (no input) and boot B (five bytes fed at 25 s) each with `irq ok rounds=2`, `rx
  on`, `open.deny ok n=11`, all twenty `init:` lines and no `FAIL`. With two throwaway probes (a
  diag in `service_rx`, a `read(0)` in init; both restored from snapshot, `grep -rn MUTATION` empty)
  the whole path ran once: `cons.park` → `rx got n=5` → `stdin got=hello` — **the first boot to
  exercise Task 2's park and retry.** **Corrected:** the spec and this plan called the moved marker
  `fs.deny`; it is init's `open.deny` (`[diag vfs] fs.deny ok n=14` is VFS's and is unmoved).
  **Rulings:** (a) the answer order zero → no-line → empty → copy is the pure `cdev::read_plan`; (b)
  `rx overflow` prints when `dropped() == 1`, no extra flag; (c) a notification in the RX phase
  without the line's bit is ignored and not counted toward the storm; (d) on a failed re-arm the
  bytes already drained still wake the waiter; (e) **`EIO` covers only a refused claim** — a failed
  TX proof, `rx FAIL storm` and `rx FAIL enable` leave a reader parked on `EAGAIN` for good, each
  behind a forbidden marker that already fails the boot. *If wrong:* about five lines to answer
  `EIO` from `Phase::Stopped` and send one wake-up `NOTIFY`. **Prediction revised for Task 7:**
  mutation 6 (skip the drain) may leave a silent stuck byte rather than a storm, because the ICR
  write comes first and QEMU drops the level on it.

- **Task 4.** init's `fork_stdin_probe` (after `announce`, before `fs_demo`), the child's read loop
  and verdict, the pid-keyed reap; `tools/feed-console.sh`; three expected markers and `stdin FAIL`
  forbidden in the common pair. Three host tests in init, its first — one `include_str!`s the feeder
  and compares its `PROBE` with `CONSOLE_PROBE` (seen failing with the script's string altered).
  Verified: four fed stub-free boots, each `cons.park` (line 622) → `cons.beside ok` (625) → `stdin
  ok n=15` (925–984), no `FAIL`; an unfed one with the first two and no `stdin ok`; **one fed full
  musl disk boot, `check-boot-log.sh disk` PASS on all 172 marker checks** (`cons.park` 36011,
  `cons.beside ok` 38259, `stdin ok` 39705, fed 25 s in); the feeder's six edge cases without QEMU.
  **Corrected in the spec:** the feeder exits after its one write instead of holding stdout open
  (R11.2), and the marker carries init's `minix.rs init:` prefix. **Rulings:** (a) **no proof child
  under `idle-probe`** — `idle_park` waits for `ECHILD` and a parked child never exits, so that
  hand-run configuration does not exercise RX; (b) the parent checks the child's exit status (PASS
  `0x53`, FAIL `0x46`) and prints `stdin FAIL no-verdict` for anything else; (c) the child asks for
  64 bytes, so trailing input in the same batch is a FAIL; (d) the feeder needs the marker on two
  consecutive polls, against a stale log from a previous boot at the same path; (e) the feeder's
  ceiling defaults to 1800 s, no stall detection; (f) **`cons.beside ok` is ordered, not
  synchronised** — the fork precedes init's first file read and `fileio` reads `/etc/motd` every
  fourth rotation turn for ever, but nothing makes init wait for the child to park. *If wrong:* (a)
  is a `cfg` to drop once the idle debt is paid; (f) would need a VFS-visible sync point, which this
  slice deliberately does not add.
- **Task 5.** `ci.yml`: the disk and ramdisk boots take `< <(FEED_CONSOLE_CEILING=1300
  tools/feed-console.sh <log>)`; the reboot is unfed. Not run — CI is not triggered from here.

- **Task 6.** Recorded boots, musl flavour, 600 s. **First set (superseded):** disk and ramdisk PASS
  at 172, reboot PASS at 7, `diff-backends.sh` clean — but the budget reading was wrong: `pm-exit
  reset closed=1` at 76.62% of the disk log and 50.59% of the ramdisk one, against 6.4's 65.57%. A
  boot of `main` on the same machine read **64.71%**, so the slice had moved it. **Root cause**
  (every marker up to `exec stack ok` was at the same byte position in both logs; the gap was one
  rotation turn, about 6.9 MB of log): the rotation `wait()` that reaped the console-read child
  reaped no rotation child, so the rotation ran one child deeper for the rest of the boot. Task 4's
  comment there said the reap "costs this cycle nothing". **Fix:** init waits once more in that
  turn. **Second set, final code:** budget **64.94%** disk (about 390 s) and **42.73%** ramdisk
  (about 256 s) — back at the baseline, no timeout moves. The fix exposed a marker that had been
  passing by luck: `[ksys SYS_EXEC] target=19 name=worker` and `[ksys SYS_EXIT] target=w nr=19`
  assumed `worker` in the fork pool's first slot, which the console-read child now takes; before the
  fix a later `worker` happened to land in 19 inside the head-carved window. **Ruling:** the markers
  are re-aimed at slot 20, which is fixed on fed and unfed boots (the child, parked or zombie, holds
  19 until after the rotation's first fork), and `child_nr=20` is added. With that: disk **PASS
  173**, ramdisk **PASS 173**, reboot **PASS 7**, `diff-backends.sh` clean. *If wrong:* the
  alternative is slot-agnostic markers (`name=worker src=name entry=`), which give up the slot
  number. **Also in this commit, from Task 8's read-only sweep:** TTY drops any `NOTIFY_MESSAGE` not
  from `HARDWARE` instead of replying `ENOSYS` to it (unreachable today; 6.8's keyboard driver will
  send one); VFS's `GRANT_SLOTS` comment and the marker file's "every turn" corrected. **Not done:**
  the generated-header diff against `main` — `kernel-shared`'s whole diff is `///` lines, verified
  by reading the diff.
