## 3. ELF loader

`/Users/kevinbarnard/src/minixrs/kernel/src/boot_image/elf.rs`:
- **Interface:** `pub fn load_into(elf: &amp;[u8], aspace: &amp;mut AddrSpace) -&gt; Result&lt;u64, ElfError&gt;` (elf.rs:90) — returns `e_entry`. **Input is a plain byte slice; it does not care where the bytes came from.** All field reads are explicit `from_le_bytes` (elf.rs:70-86) precisely because the input carries no alignment guarantee (elf.rs:13-15).
- **Assumptions:** `ET_EXEC` only (elf.rs:103, `BadType`), ELFCLASS64 + LSB + EM_AARCH64, `e_phentsize == 56`. Per segment: **`p_vaddr` AND `p_offset` must both be 4 KiB-aligned** and `p_filesz &lt;= p_memsz` (elf.rs:148, `Misaligned`); `p_offset + p_filesz &lt;= elf.len()`; **W^X enforced** (elf.rs:162, `WriteExec`). No PIE/ET_DYN, no relocations, no PT_INTERP, no PT_TLS handling, no `p_align` respect beyond page.
- **Mapping:** one `alloc_frame()` per page of `p_memsz`, copy via `phys_to_hhdm`, `flush_icache_range` if executable, `aspace.map_page` (elf.rs:172-197). BSS is free because frames are zeroed on hand-out.

Wrapper: `/Users/kevinbarnard/src/minixrs/kernel/src/arch/aarch64/userland.rs:339` — `pub(crate) unsafe fn load_exec_image(elf: &amp;[u8]) -&gt; Option&lt;ExecImage&gt;`; `ExecImage { ttbr0_pa, asid, entry, sp_top }` (userland.rs:319-324). Builds `AddrSpace::new()`, loads, maps **exactly one** RW stack page at `SERVER_STACK_VA`, allocates an ASID, `mem::forget`s the AddrSpace. On any failure it runs `destroy_addrspace_with_leaves` (userland.rs:389) so nothing leaks. **`sp_top = SERVER_STACK_VA + PAGE_SIZE` — a single 4 KiB stack, no argv/envp/auxv construction at all.**

`SYS_EXEC` (`/Users/kevinbarnard/src/minixrs/kernel/src/system/do_exec.rs:71`): payload is `[0..4] = target endpoint`, `[4..4+EXEC_NAME_LEN] = NUL-padded name`. It resolves the name via `BootImage::get().module_by_name(name)` (do_exec.rs:106) which returns a `&amp;'static [u8]` into the `include_bytes!`-embedded MXBI archive (`/Users/kevinbarnard/src/minixrs/kernel/src/boot_image/mod.rs:34, :113`). Rejects `SELF`/caller (active-TTBR0 hazard), requires target be a clean `RTS_RECEIVING` blocked receiver with no `MF_DELIVERMSG` (do_exec.rs:116). Loads new image first (untouched-on-failure), then swaps, tears down old AS via `do_exit::teardown_addrspace`, `rts_unset(RTS_RECEIVING)`.

**Could it load ELF bytes from a user-space server?** The loader itself, yes — it takes `&amp;[u8]` and makes no static-lifetime demand. What's missing:
1. **A way to get the bytes.** There is no bulk user→kernel copy. You'd need `SYS_SAFECOPY`/grants or a VM-mapped shared buffer, plus the fault-recovering copy from §1.
2. **Kernel-side staging.** No kernel heap (`no_std`, no allocator visible) — you'd need to stage into frames from `mm::alloc_frame` and hand `load_into` a slice over the HHDM alias, or teach it a chunked/reader interface.
3. **Hardening.** Today `ElfError` variants are documented as "all fatal at boot (the embedded VM ELF is produced by our own build, so any of these means a build/loader bug)" (elf.rs:23-24) — the checks exist and are sound, but a hostile-input review is warranted (notably `e_phoff + i*56` arithmetic is checked only by `rd_*`'s slice `get`, which is fine, and `p_memsz.div_ceil(PAGE_SIZE)` has no cap → a huge `p_memsz` is a frame-exhaustion DoS, bounded only by `alloc_frame` returning `None`).
4. `ET_EXEC` + `p_offset` page-alignment means musl-produced binaries need `-static` and a linker script matching `servers/*/user.ld`; a stock musl static link will usually satisfy `ET_EXEC` but **not necessarily the `p_offset` page-alignment requirement** — that's the likeliest breakage.
5. The `SYS_EXEC` payload carries a 16-byte name, not a pointer/length — the message ABI would need a new sub-form.

## Phase 5 implications (condensed)

Three independent gaps, in increasing order of cost:
1. **Console for servers** — `SYS_DIAGCTL` with an inline-payload buffer. No new infrastructure needed; the number, the mask bit, and the dispatch arm all already exist.
2. **Grants/safecopy** — `Priv.grant_table`/`grant_entries` are declared but there is no grant type, no `SYS_SETGRANT` body, and no cross-AS copy primitive. `AddrSpace::walk_pt` (`/Users/kevinbarnard/src/minixrs/kernel/src/arch/aarch64/addrspace.rs:129`) plus `map_page_in`'s "all table access is via HHDM; the target AS need not be the active one" property (addrspace.rs:172) gives you the mechanism for a page-at-a-time cross-AS copy without switching TTBR0.
3. **Fault-recoverable kernel access to user memory** — currently absent by design and by hardware wiring. Requires a real `el1h_sync` handler replacing `EXC_ENTRY el1h_sync, 4` (vectors.S:80), plus a fixup mechanism. This is the prerequisite for trusting *any* user-supplied pointer, and also for making `flush_deliver_msg`'s currently-swallowed error (`ipc/mod.rs:284`) meaningful.</result>

### **Can a non-ELF blob be packed?** — Yes, with no format change.
1. `pack_mxbi` takes opaque `Vec&lt;u8&gt;` and does **zero** content validation (`build.rs:238-278`).
2. `BootImage::get()` validates only magic/version/table-bounds and per-record `offset + len &lt;= bytes.len()` (`boot_image/mod.rs:53-77`) — never touches payload content.
3. The boot loader **explicitly skips negative `proc_nr`**: `kernel/src/arch/aarch64/userland.rs:184-190` — `if nr.get() &lt; 0 { continue; }`, comment cites `com::EXEC_ONLY_PROC_NR`. So a module tagged `-1` is never ELF-parsed at boot.
4. `BootImage::module_by_name(&amp;str) -&gt; Option&lt;&amp;'static [u8]&gt;` (`mod.rs:113-119`) returns **raw bytes with no ELF check**. Only `do_exec.rs:106` feeds the result to `elf::load_into`, which is where `ElfError::BadMagic/BadClass/BadType` (`boot_image/elf.rs:29-40`) would fire.

So an initramfs / MFS disk image can be packed today as `("initramfs", bytes, -1)` and retrieved by name. Constraints to design around:
- The whole archive is `include_bytes!`'d into kernel `.rodata` (`mod.rs:34`), landing in Limine's `EXECUTABLE_AND_MODULES` region — **never freed, and it inflates the kernel binary 1:1** with the image size. A multi-MiB FS image is a real cost.
- `offset`/`len` are `u32` → 4 GiB cap (fine).
- `build_server` assumes every module is a cargo crate; a raw blob needs a separate `std::fs::read` path in `build_boot_image`.
- Name field is 20 bytes NUL-padded, but `EXEC_NAME_LEN = 16` (`callnr.rs:66`) bounds what `SYS_EXEC` can carry — a longer blob name is reachable only from kernel-internal callers.
